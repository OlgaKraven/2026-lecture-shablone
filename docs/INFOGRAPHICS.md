# Библиотека инфографики

Все примеры доступны в демонстрационной лекции **«Библиотека инфографики»**, ID `VISUALS`. Это готовые SVG-компоненты с данными, а не задания нарисовать схему позднее. Сравнения и матрицы также рендерятся векторно. Изображение с выносками использует реальный снимок каталога.

| Вид | Поле `visual.type` | Основные данные | Ограничение одного слайда |
|---|---|---|---|
| Последовательность действий | `process` | `items: [{title, text}]` | 2–4 этапа |
| Алгоритм с условиями | `decision` | `start`, `question`, `yes`, `no` | Одна развилка; дальнейшие проверки на следующем слайде |
| Циклическая схема | `cycle` | `items: [{title, text}]` | 4 этапа, замыкающая стрелка |
| Устройство системы | `network` | `nodes`, `edges: [{from,to,label}]` | 2–4 узла, направленная последовательность |
| Иерархия | `tree` | `root`, `branches: [{title,items}]` | До 4 ветвей, до 2 листьев на ветвь |
| Сравнительная инфографика | `comparison` | `columns`, `rows` | 3–4 колонки, до 4 строк |
| До — после | `beforeAfter` | `before`, `after`, `changes` | Две формы до 3 полей, подписи изменений |
| Карта понятий | `conceptMap` | `center`, `items: [{title,example,relation}]` | 6 понятий с подписанными связями |
| Схема состояний | `states` | `states`, `cancelFrom` | 5 состояний, отдельная отмена |
| Причина — следствие — решение | `cause` | `cause`, `effect`, `solution` | 3 связанных смысловых блока |
| Изображение с выносками | `callouts` | `image`, `alt`, `items: [{x,y,title,text}]` | До 4 отметок; координаты 0–100% области картинки |
| Разбор объекта по частям | `codeParts` | `parts: [{code,label,explanation}]` | До 4 фрагментов; короткие строки кода |
| График или диаграмма | `bars` | `items: [{label,value}]`, `max`, `unit`, `threshold?` | До 3 рядов, явная шкала от нуля |
| Матрица соответствий | `matrix` | `columns`, `rows` | До 4 колонок и 4 строк; символ и текст в ячейках |

Дополнительно доступна `timeline` — временная последовательность 2–4 этапов. Условные интервалы не выдаются за реальные длительности.

У всех типов обязательно поле `caption`: учебный вывод и необходимые условия. Для реальных количественных данных нужен источник; для условных — подпись «Учебные данные». Длинные подписи и более сложные структуры разбиваются на несколько слайдов. Ограничения являются частью контракта первой версии, а не разрешением обрезать лишнее.

Пример:

```json
{
  "type": "decision",
  "start": "Отправка формы",
  "question": "Все обязательные поля заполнены?",
  "yes": "Следующая проверка",
  "no": "Показать ошибки",
  "caption": "Заполненность полей ещё не означает корректность всех данных."
}
```

Перед генерацией выбрать вид по учебному отношению: порядок, условие, цикл, состав, сравнение, связь, состояние или количественное изменение. Не заменять различающиеся отношения одной декоративной сеткой карточек.

На широком экране схема вписывается в слайд. На телефоне для сложной схемы допустима локальная горизонтальная прокрутка самой иллюстрации; заголовок, подпись и остальная страница не должны обрезаться или расширять экран.
